QUICK START / S1 → DN → S2

Five decisions before implementation.

The first useful artifact is not an autonomous agent. It is a testable participation whose communication and outcome can be examined.

Name the situation and observation.

Establish the governing Space and declare the Pulse name, Response schema, and Y/U/N meaning. Example: customer_id / Y / CUST-101.

Declare why it is being sent.

Choose an explicit Intention such as I_OrderDraftRequested. Do not leave purpose implicit in a URL or handler.

Form the complete input Signal.

Combine the Intention with exactly the required Pulse set. Reject missing, duplicate, or undeclared observations before activation.

Bind one bounded DN.

Implement a stub that accepts S1 and emits the declared S2. Keep all Response-changing computation inside the DN.

Test success, conflict, and unresolved outcomes.

Exercise Y, N, and U before connecting real services. Preserve the returning resolution when S2 becomes a later DN’s input.

REALISTIC COMMERCE REFERENCE

Node.js Orders. Spring Boot Inventory. Explicit resolution.

The downloadable lab combines a Python contract engine and agent policy layer with independent enterprise applications. It supports deterministic scripted runs, local Ollama, or an API-hosted OpenAI-compatible model.

Orders implements drafts, submission, decision recording, state guards, idempotency, and optimistic concurrency. Inventory implements transactional reservations, stock locking, idempotency, and fault injection.

Prototype and real HTTP adapters share the same DN contracts. Tests distinguish business Y/U/N from transport success. Provenance records each situated DN activation.

NEXT IMPLEMENTATION / DESIGN TARGET

From one agent to governed cooperation.

The current Python runtime is a single CommerceAgent coordinating four DNs. The revised design separates independent OrderingAgent and InventoryAgent participants.

IS_OrderManagement / v1 and IS_InventoryManagement / v1 retain local semantics. Colosseum C04 governs reservation request and decision C–MAPs. OrderingAgent must request InventoryAgent rather than directly activating its DN.

No distributed ACID transaction is assumed. Idempotency, explicit states, independent observation, reconciliation, and later compensation address partial failure.
