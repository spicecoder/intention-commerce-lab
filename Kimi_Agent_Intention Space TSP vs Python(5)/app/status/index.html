PUBLIC CLAIM BOUNDARY

Capability should have an evidence state.

A concept, a browser interaction, a prototype, a real-service integration, and a production release are different claims. This page keeps them separate.

Unified site profile: static, frontend-only reference experiences. No account, remote model, cloud database, or durable application state is used.

STATUS VOCABULARY

Four labels, no implied production readiness.

Verified

The displayed browser capability is implemented and exercised in the real page.

Session-only / prototype

A bounded implementation exists within the stated local or browser boundary.

Experimental

The capability is suitable for exploration, not a stable production release claim.

Design target

The architecture or acceptance criteria are documented; implementation is not claimed.

CAPABILITY / EVIDENCE MATRIX

What this unified site actually provides.

Verified

Multi-page explanatory site

Static HTML, responsive layouts, keyboard-operable navigation, and local assets. No runtime activation is required to read it.

Verified

Signal identity laboratory

Deterministic browser construction, semantic fingerprinting, duplicate-Pulse and invalid-TV diagnostics. It does not assess real-world truth.

Session-only

Commerce reference microscope

Computed display of embedded Commerce declarations and scenario resolutions. It is not a live Orders or Inventory transaction.

Verified

Exact six-domain TSP

Held–Karp dynamic programming in browser JavaScript. Weights are illustrative cost pressures, not reliability or importance scores.

Verified

Participation checklist

Copy and print the current twelve-item state. Progress is not stored after leaving or reloading the page.

Prototype

Python Commerce lab

Recorded deterministic prototype tests and direct HTTP integration checks. Live Compose, PostgreSQL, Ollama, and API calls remain local-environment work.

Prototype

Node.js and Spring Boot applications

Realistic independent application code and tests. The downloadable archive is source material, not a hosted production commerce service.

Reference pattern

Guarded DN_LLM

The bounded-provider pattern and optional lab clients are described. No remote model is hosted or invoked by this static site.

Design target

Independent OrderingAgent and InventoryAgent

Versioned Spaces, C04 C–MAPs, reconciliation, and MA-01–MA-18 acceptance criteria are designed; the two-agent implementation is not claimed complete.

Design input

Site phrase catalogue and arbitrary package execution

Semantic catalogues do not by themselves authorize runtime execution. Arbitrary uploaded-package execution is not offered here.

Claims this site deliberately avoids.

Natural-language contracts do not guarantee shared understanding. Prototype success does not prove real implementation correctness. Package integrity does not prove semantic correctness. Validation does not make an LLM truthful. A Colosseum does not create universal trust. Human prosperity is a social outcome to evaluate, not a property automatically conferred by software architecture.
