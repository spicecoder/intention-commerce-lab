LOCAL DN / IMPLEMENTATION PORTABILITY

One Signal contract. Your execution environment.

A Local DN absorbs one declared Signal form, performs a bounded action, and emits one declared Signal form. The registry binds that semantic contract to executable code without putting language-specific implementation into the application manifest.

Status: reference implementations and registry patterns are prototype material; public release packaging remains a separate gate.

CROSS-LANGUAGE REFERENCE

Alphabetical ordering as a conformance fixture.

DN_OrderBoxesAlphabetically absorbs S_OrderBoxes and emits S_BoxesOrdered. JavaScript, Python, and Java implementations can be tested for equivalent Pulse identities and Responses.

Package:
DN_OrderBoxesAlphabetically / 1.0.0

Absorbs  S_OrderBoxes
Emits    S_BoxesOrdered

Verify   local-dn/cli.mjs verify <package>
Install  local-dn/cli.mjs install <package>
Inspect  local-dn/cli.mjs list

The example illustrates implementation equivalence. It does not make arbitrary uploaded code safe to execute.

PACKAGE INTEGRITY

Integrity is necessary, not sufficient.

A versioned registry can install, list, inspect, resolve, and verify a DN package. Digest checks reject modified or undeclared content and bind implementations to the expected Signal forms.

A verified digest establishes that bytes match an expected artifact. It does not establish semantic correctness, business safety, or authority to execute. Uploaded packages still need bounded admission, isolation, and approval.

Local and remote activation can sit behind the same IC contract: the IC controls readiness and output admission while the provider controls placement.
